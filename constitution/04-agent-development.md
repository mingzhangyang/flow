# Agent 开发原则

整个开发项目围绕 **Agent** 组织，而不是围绕 IDE。以下约束保证：无论谁（哪个模型）来写代码，方向都一致，架构不腐化。

**C7 — 所有知识首先写给 Agent，而不是写给程序员。**
产品的哲学与结构写在 `constitution/` 与 `docs/` 里。一个 Agent 应能**仅凭这些文档**理解整个产品，再开始写代码。

**C8 — 任何需求都必须追溯到宪章。**
新增一个功能（例如"分支节点 Branch Node"），Agent 必须能回答：**它满足哪一条 Constraint？** 回答不了，说明这个功能值得重新思考。
落地约定：每个 PR / commit 写一行 `Constitution: C_` 说明所服务的约束（见 `README.md`）。

**C9 — Agent 优先维护 Architecture，而不是代码。**
AI 很容易不断生成代码，却让架构逐渐混乱。因此**实现任何新功能之前，先回答这三个问题**：

1. 这个功能属于**哪个领域 / 模块**？
2. 它会不会**破坏现有抽象**？
3. 能不能通过**扩展**而非**修改**来实现？

三个答案清晰之前，不写代码。

**C10 — 任何模块都应能被 Agent 单独重建。**
Timeline Renderer、Runtime Engine、Notification Engine、Storage、AI Assistant 之间**只通过明确接口通信**。为了让"单独重建"不只是愿望，配套机制是：

- 模块边界定义为**类型化接口 + 契约测试（contract test）**；
- Run 的**重放日志作为黄金主测试（golden-master）**（见 E4）。

有了这两样，Agent 才能独立重构某个模块而不破坏整个系统。

---

## 每次开工的检查清单

1. 读过相关的 `constitution/` 与 `docs/` 了吗？
2. C9 的三个问题答清楚了吗？
3. 本次改动追溯到哪几条 Constraint（写进提交信息）？
4. 是否新增或改动了模块接口？若是，契约测试更新了吗？
5. 是否触碰不可变原则？若是，先写 ADR。
