# ADR 0001 — 宪章 v1：整合审查意见

- 状态：已接受
- 日期：2026-07-01

## 背景
产品先有一份"产品宪章"草案（使命/愿景/第一原则/AI 原则/Agent 开发原则/技术约束）。
在动代码前对其做了一轮审查，发现若干结构性缺口会直接影响核心数据模型。

## 决策
将宪章修订为 `constitution/` 层（一屏一文档，挂接到 `AGENTS.md`），并整合以下审查结论：

1. **Flow（定义）≠ Run（运行实例）** 升为一级概念——化解 C5/可重放/AI-C1 之间的张力。
2. **两种时间拓扑**（顺序型 + 日程/并行型）都是一等公民——防止创始场景（服药）被设计出局。
3. **时钟为显式输入**，且**确定性 = Flow 定义 + 注入时钟 + Run 事件日志**——让 E4 与 C5 互补而非冲突。
4. **节点携带可选 rationale（"为什么"）**——把"Flow 是知识"落到 schema。
5. **v1 只用一种可读格式，暂不自研 DSL**——对宪章自身应用 Constraint 0。
6. **Schema 版本化**——保障可分享/持久的 Flow 不因升级损坏。
7. **医疗安全原则（E6）**：描述性而非处方性，分享带 provenance 与免责。
8. **C10 配契约测试 + Run 重放黄金测试**——让"模块可单独重建"有牙齿。
9. **Constraint 0 前置**，新增**"Flow 不是什么"反目标清单**。
10. **Constitution Layer 机制**：短文档、追溯约定、区分不可变原则与可修订实现、自身版本化。

## 影响
- 领域模型（Phase 0）据此构建。
- 后续任何对**不可变原则**的改动，都需新增 ADR。
