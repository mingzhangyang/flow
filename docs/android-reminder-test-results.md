# Android 提醒真机验证记录模板

> 本表只记录发布候选版本（RC）的可复现证据。复制为
> `docs/release-evidence/android-YYYYMMDD-<short-sha>.md` 后填写；不要记录 adb serial、账号、
> 药名、服药时间或其它个人健康信息。

## 安全边界（E6）

- 本次测试使用非医疗示例内容或虚构标签，不改变任何人的真实医嘱。
- 即使测试提醒看似可靠，也不把内测版作为真实服药的唯一提醒。
- `force-stop` 后 Android 在用户重新打开应用前不保证通知；该项验证平台边界，不要求提醒响。

## 必测结果

“实际结果”记录计划时刻、实际响铃时刻、偏差秒数、声音/横幅表现和必要截图文件名。

| ID | 场景与操作 | 预期 | 实际结果 | 结论 |
|---|---|---|---|---|
| A01 | 全新安装（或确认备份后清除测试数据），启动后再首次打开服药示例 | 权限框只在首次登记提醒时出现，不在启动时出现 |  | ⬜ |
| A02 | 允许权限，安排 2–3 分钟后的提醒，App 保持前台 | 到点显示横幅并播放默认声音 |  | ⬜ |
| A03 | 安排提醒，按 Home 进入后台 | 到点提醒正常 |  | ⬜ |
| A04 | 安排提醒并进入后台，运行 `process-death` | 普通进程死亡后，到点提醒仍正常 |  | ⬜ |
| A05 | 安排未来提醒，运行 `reboot --confirm`，设备重启后不先打开 App | 到点提醒正常；若失败，记录 boot receiver / 调度状态 |  | ⬜ |
| A06 | Android 12+ 授予“闹钟和提醒”，安排提醒后运行 `doze-enter` | Doze 中不提前且延迟不超过上表容差；结束后运行 `doze-exit` |  | ⬜ |
| A07 | Android 12+ 撤销“闹钟和提醒”，重复 Doze 测试 | 行为被准确记录；若明显延迟且 App 无提示，不得放行 |  | ⬜ |
| A08 | 拒绝通知权限，再进入日程视图并点“去系统设置”，开启后返回 | 显示警示横幅；设置跳转有效；返回后横幅消失 |  | ⬜ |
| A09 | 创建锚定 IANA 时区的 flow，排提醒后修改设备时区 | 仍按 flow 锚定时区对应的绝对时刻提醒 |  | ⬜ |
| A10 | 安排提醒后运行 `force-stop --ack-platform-limit` | 重新打开前不期待提醒；`reopen` 后为未来时刻重排并恢复 |  | ⬜ |
| A11 | 编辑/删除已登记 flow | 旧提醒被替换/取消，不产生孤儿提醒 |  | ⬜ |

结论只用：`通过` / `失败` / `阻塞`。A07 若暴露静默延迟，属于发布阻塞，不得仅标注“平台限制”。
